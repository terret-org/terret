# M8: Subagents, then 0.1 Release — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship M8 from `docs/terret-implementation-plan.md` §12: the `Task` tool over a new `ctx[:subagents]` seam, background jobs over `ctx[:jobs]`, an ACP server, docs and cookbook, `doctor`, the bench lane, the §13 security pass, the RubyGems 0.1.0 release of all gems, and an example third-party plugin gem published from a separate repo to prove the extension story.

**Architecture:** Two new capability seams in existing gems (subagents in terret-core over the agent registry's fork machinery; jobs in terret-exec over the subprocess seam), three tools on top of them (`Task`, `job_*`, `TodoWrite`), and the composition layer the release stands on: `gems/terret` stops being a placeholder and gains §7's bundles/profiles/patches, `Terret.boot(profile:)`, the `terret-base` bundle, a non-interactive `bin/terret` (boot/doctor/dump-config), and `doctor` validating every row against a new lightweight `Hames::Schema` — which also generates `docs/config-catalog.md`. `terret-acp` is a twelfth gem: a JSON-RPC-over-stdio Agent Client Protocol server mapped onto `ctx[:agents]` and `session/event`. The security pass and the release run LAST, in that order, after both adversarial gates.

**Tech Stack:** Ruby 4.0.6, plain minitest, stdlib only in hames/terret-core/terret-exec/terret (optparse, yaml, json are stdlib). `terret-acp` is stdlib-only too (JSON-RPC over stdio needs no HTTP). No dry-schema — the plan's §10 mention is superseded by `Hames::Schema` (zero-dep constraint wins; note the drift in §14 at docs sync).

## Design decisions already made (do not relitigate mid-task)

- **ACP ships despite §9.5.** §12's milestone line governs the roadmap (CLAUDE.md: "phases are in its §12"); §9.5's "None is v1" loses. Scope is the SERVER only — editors drive a Terret agent. The ACP *client* subagent provider from §6.8 is recorded in §14 as deferred, alongside the pooled-worker provider from §6.4.
- **Tool names**: `Task` and `TodoWrite` — Claude Code's names verbatim, the M7 rule (§6.7 wrote lowercase `task`/`todo` before the names-verbatim decision hardened; the rule wins). Job tools have no CC equivalent, so like `terminal_*` they are snake_case: `job_start`, `job_collect`, `job_stop`.
- **The default subagent provider is a fork.** `ctx[:subagents]` is a sole-provider seam (the summarizer/session_store pattern). The core provider forks the *calling agent's* context, spawns a child agent there (so the child sees the parent's roster and policy floor — deny-by-default carries over), runs a fresh session to completion, returns `{text:, session_id:, usage:}`, disposes the child. The child's session is durable and titled like any other; the parent's log sees only the tool result (model-visible = logged holds with no new durable events).
- **Jobs are session-scoped and NOT durable.** `ctx[:jobs]` lives in terret-exec (it needs `ctx[:subprocess]` and the sandbox seam). A job survives its turn but not the process; restart-surviving jobs are a recorded §14 non-goal for 0.1. Jobs die with their agent via the existing `agent/disposed` listener pattern, buffers are byte-capped (M7's cap discipline), and `job_start` wraps argv through `ctx[:sandbox].wrap` exactly like Bash.
- **`TodoWrite` state is model-visible, therefore logged**: the tool result echoes the full list back, and that is its only storage — no service state, no new event. Rendering is the tool result; the invariant does the persistence.
- **The tool barrier lands with the `Task` tool** (M7 declared `concurrency:` as metadata for exactly this): within one assistant message, consecutive calls whose definitions say `:parallel` run concurrently under an Async barrier; `:serial` calls and order-dependent semantics stay sequential. Results append in CALL ORDER regardless of completion order — the log's determinism is not negotiable.
- **Status machine, minimal honest version**: add `:stopping` (set when a cancel is requested, cleared at `turn/end`) and `:done` (set by `dispose_agent`, terminal). `:waiting_approval` stays. `:waiting_input` is NOT implemented — no consumer exists; record it in §14 as vocabulary reserved.
- **`Hames::Schema`, not dry-schema**: a class-level `config_schema` declaration on `Hames::Service` — `{key => {type:, required:, enum:, default:, doc:}}` — validated by pure stdlib. Services without a schema validate as "anything goes" (doctor reports them as unschema'd rather than failing them). `docs/config-catalog.md` is generated from these declarations by `rake config:catalog` and CI-diffed like events.md.
- **`terret-base` is a bundle resource inside the meta-gem** (`gems/terret/config/bundle.yml`), not a separate gem — §5's diagram lists no such gem and §7 says "inside the meta-gem". Its rows: sqlite store, openrouter adapter, std tools, exec seams, **docker sandbox with `network: none`** (secure by default per §13 — the headless template's patch.yml shows the explicit loud-comment opt-in to `none`), redactor, approvals (disabled: true — opt-in per M6), allow-list floor.
- **The executable is `trt`** (`gems/terret/exe/trt`) — the placeholder gemspec and cli.rb already name it ("the trt CLI"); code is current, and the plan document never names a binary at all. Non-interactive and minimal: `trt boot --profile NAME [--patch FILE] [--allow-config-ruby]`, `trt doctor --profile NAME`, `trt dump-config --profile NAME`, `trt acp --profile NAME` (Task 7). optparse, no thor, no TUI, no REPL — §1's non-goals bar interactivity, not executables. `Terret::CLI::VERSION` drift is fixed by reading the gemspec's single source (a `Terret::VERSION` constant both use). cli.rb's stale "M4 work / M2 outstanding" comment dies in the rewrite.
- **`ctx[:credentials]` (§6.9) lands in the security pass** — docs/security.md and docs/exec.md both already promise it for M8, so re-deferring would mean editing shipped promises instead of keeping them. Minimal honest version in Task 11: ENV always wins (resolve by provider name), an optional encrypted file store (AES-256-GCM via stdlib openssl, master key from `TERRET_CREDENTIALS_KEY`, refuse plaintext), and every resolved value auto-feeds the redactor's pattern set — that last part is the security payoff the docs point at. OS-keychain backend stays §14.
- **Tagged scalars**: `!env NAME` (ENV fetch, nil if unset), `!setting dotted.path` (resolved against the profile's `settings:` map), `!ruby` refused unless `--allow-config-ruby` (then `eval` in a clean binding — config is data first, and the flag is the consent). Implemented with `YAML.safe_load` plus explicit tag classes; never `YAML.load`.
- **Release is lockstep 0.1.0** for all twelve gems (terret 0.0.2 → 0.1.0 included), `metadata["terret"]` landing on every gem that ships a bundle, a `rake release:build` + `rake release:push` pair (push iterates in dependency order), git tag `v0.1.0`. The example third-party gem also goes to RubyGems — install-and-discover is the proof, not just a repo link.
- **The example gem is `terret-fortune`**: one tool (`fortune`, returns an aphorism from a vendored list), `config/bundle.yml`, `metadata["terret"]`, its own repo under the `obie` GitHub account, its own minitest, README that IS the extension story told end-to-end. Cookbook's adding-a-tool page and this repo must agree because the repo is the cookbook page made real.

- **Do not relax invariants**: model-visible means logged; deny-by-default fails closed; registration is reversible through effects; durable-first append ordering; one reactor — a blocking read that doesn't park the fiber stalls every agent.

### Task 5.5: Mid-milestone hardening (from the Codex challenge + opus whole-M8 checkpoint after Task 5)

The two adversarial gates over the whole M8 diff (9b36be7..HEAD) found lifecycle/concurrency bugs no single per-task review could see. These are correctness/liveness on the foundation Tasks 6-12 build on — fixed here, before proceeding. All TDD, failing-first. Security-flavored findings (floor-only policy inheritance for children; unbounded child-session accumulation) are deferred to Task 11; forward items (version single-source → Task 12; doctor materialize-then-validate → Task 6; cancel-cascade into parallel children → Task 7) are recorded against those tasks.

- [ ] **Reactor starvation from a continuously-writing job** (Codex P1): `Jobs#pull` and `PipeHandle#drain` loop until the pipe is momentarily empty with no yield/budget, so a child that keeps the pipe readable starves every other fiber on the one reactor — and `end_group`'s drain runs before its deadline check, so a TERM-ignoring writer can prevent SIGKILL forever. The Task-3 cap bounded MEMORY, not reactor occupancy. Add a per-pass byte/iteration budget with a scheduler yield, and check the deadline inside `end_group`'s drain loop. Defends the one-reactor invariant.
- [ ] **Duplicate tool-call IDs deadlock parallel approvals** (Codex P1): providers can emit non-unique call ids; approval waiters keyed by `[session_id, call_id]` mean a second parallel call replaces the first's queue, one resolution wakes only the replacement, and the first fiber parks forever (barrier never completes). Key waiters by a unique per-park token, not the call id.
- [ ] **Shutdown doesn't dispose agents** (Codex P1; opus's forked-context nuance): `Boot.shutdown` unloads rows but `Loop` has no `stop` hook disposing `@agents`, so idle agent forks and their effects (per-agent policy listeners, forked tool registrations) survive teardown. Give `Loop#stop` disposal of every agent it holds; verify against opus's "reverse_each+dispose! HOLDS at row level" — the gap is agent-fork level, below the row.
- [ ] **Mount/unload not exception-safe** (Codex P1, hames kernel): `Loader#mount` records the plugin only after `apply`, so a plugin that registers then raises leaves live registrations absent from `mounted` (partial-boot can't tear down); `unload!` deletes the entry before `stop`, so a raising `stop` loses owner effects and can't retry. Make both exception-safe (record/roll-back around `apply`; keep the entry or dispose owner effects if `stop` raises). Invariant-sensitive — TDD carefully.
- [ ] **Subagent dispose ordering exhausts the cap** (Codex P1; overlaps Task-2 deferred finding 5): `dispose_agent` disposes the fork before removing the registry entry, so a raising disposer leaves the child registered and `Subagents#dispose` only warns — repetition exhausts `max_agents`. Remove the registry entry in an `ensure` regardless of disposer raise.
- [ ] **VERIFY-FIRST: does a failed turn's dangling tool_call poison future turns?** (Codex P1): a raise in a serial/singleton tool call (the pre-M8 N=1 path Task 2 scoped out) closes `turn/end: failed` with the `tool/call` logged and no `tool/result`; if `derive_messages` then includes that dangling assistant tool_call in the NEXT turn's context, every future provider request is malformed (assistant tool_use with no tool_result) — terminal. Write the reproduction test FIRST. If it reproduces, fix (synthesize an error `tool/result` for calls a failed turn owed, or guard the serial path like the barrier's parallel path); if it does not (resume/derive already handles it), record why and close the finding. Report the verdict either way.
- [ ] **`examples/web_chat.rb` leaks jobs on shutdown** (Codex P1): its ensure closes shell/terminals/sandbox but never stops `ctx[:jobs]`, doesn't dispose the agent/context or close SQLite via its stop hook, and a first-close failure skips the rest — and it's the console in active manual use. Route its shutdown through `Boot.shutdown` (now that Task 5 built it) or add jobs + per-step rescue.
- [ ] **CLI teardown not in an ensure** (Codex P2): any exception after `Terret.boot` succeeds jumps to the rescue and returns 1 without `Boot.shutdown`; move teardown to an `ensure`.
- [ ] **Comment overstates the floor guarantee** (opus (c) nit): `subagents.rb:12-16` says flatly a Read/Grep-restricted agent can't have a child run Bash, but that holds only for FLOOR-based restriction, not a hot-reloaded `policy/updated` narrowing (docs/subagents.md §3 has the qualifier). Align the comment with the doc.
- [ ] **Gates (both lanes) + adversarial re-review**, commits at seams.
